## 변경 사유와 증거

사용자 지시(2026-08-09 대화): 운영 환경에서는 동일 제목(`삼국지-전략판`)의
클라이언트가 복수 실행될 수 있다(예: 컬러단장용스·羊커리 계정). "羊커리
클라이언트만 사용"은 현재 테스트 세션의 한시적 제약일 뿐이며, 운영에서는
프로그램 구동 시 클라이언트를 동적으로 확인해 사용자에게 선택을 받아야 한다.

- 현행 코드 확인: `WindowSession.attach`는 다중 후보 시 오류로 거부하고
  `--hwnd` 수동 지정을 안내한다(map_search S-1 실측 유래 — 제목 기반 자동
  선택은 z순서에 따라 다른 창을 잡는 위험). CLI `probe`/`scan` 모두 동일.
- 창 제목이 동일해 제목만으로는 후보를 구분할 수 없다 — 선택 UX에 별도
  식별 수단(창 전면 표시 확인)이 필요하다.

## 기존 기준선과 설계

- REQ v2: 대상 창 선택에 관한 기능 요구사항 없음(단일 클라이언트 암묵 전제).
- DES-10 / 실패 흐름 표: "창 없음·다중 창·권한 부족·해상도 불일치 → 안내 후
  종료 코드 1". CLI는 `--hwnd` 수동 지정만 제공.

## 제안 설계

1. **FR-08 (신설)**: `scan`·`probe` 구동 시 제목 매칭으로 클라이언트 창
   후보를 동적 탐지한다. 후보가 여럿이고 대화형 실행이면 후보 목록(순번·
   pid·창 위치·크기·권한)을 표시하고 번호 선택을 받은 뒤, **선택한 창을
   전면에 올려 사용자 확인(y/n)을 받고** 진행한다(동일 제목 구분 수단).
   후보가 하나면 대상 창 정보를 출력하고 자동 진행한다. `--hwnd` 지정 시
   탐지·선택을 생략한다(자동화 경로). 비대화형 실행(stdin이 콘솔이 아님)
   에서 다중 후보면 후보 목록과 함께 거부한다(종료 코드 1, 프롬프트 대기
   금지 — 에이전트 실행기 보호).
2. **AC-07 (신설)**: 클라이언트 창 2개 실행 상태에서 대화형 scan 실행 →
   후보 목록 표시, 번호 선택·전면 확인 후 선택한 창으로 스캔 수행. 후보
   1개면 선택 절차 없이 진행.
3. **DES-10 갱신**: 창 선택 절차(`choose_window` — 선택·확인 루프, 입력
   콜백 주입으로 단위 테스트 가능)를 Controller/CLI 책임에 추가. 플랫폼
   계층(session.py)은 무수정 유지 — `find_client_windows()`를 재사용하고
   선택은 CLI 계층이 수행한다(DES-01 무수정 복사 원칙 보존).

- 진행 중인 구현: TASK-12 검증과 독립(테스트 세션은 단일 후보 또는 `--hwnd`

- 테스트와 문서: `choose_window` 단위 테스트(단일 자동·다중 선택·확인 거부·
  중단·잘못된 입력), README 사용법 반영.

## 고려한 대안

- 대안 A: 항상 확인 프롬프트(단일 후보 포함) — 기각(사용자 결정): 단일
  후보는 자동 진행으로 마찰 최소화.
- 대안 B: 목록만 표시(창 조작 없음)·순차 플래시 — 기각(사용자 결정): 선택
  후 전면 확인이 동일 제목 구분에 가장 확실.
- 대안 C: 창 스냅샷 저장 후 경로 안내 — 기각: CLI 흐름이 끊기고 전면 확인
  보다 번거로움.

## 구현된 코드의 처리

- 유지: 전체(session.py `find_client_windows`·`WindowSession` 무수정 재사용).
- 수정: cli.py의 probe/scan 창 확정 경로를 공통 선택 절차로 통합,
  controller.py에 `choose_window` 추가.
- 되돌림: 없음.

## 검증 방법

- 단위(TDD): `choose_window` — 단일 후보 자동 반환, 다중 선택→전면 확인→
  확정, 확인 거부 시 재선택, `q` 중단, 잘못된 입력 재프롬프트.

## 남은 위험

- 전면 표시(raise)가 게임 클라이언트 포커스 동작에 주는 영향은 실기 확인
  필요(입력은 PostMessage라 포커스 무관, 표시 확인용).
- AC-07 실기 검증은 두 클라이언트 동시 실행이 가능한 시점에만 수행 가능 —
  불가하면 단위 테스트 + 단일 후보 실기로 부분 검증하고 잔여 위험으로 기록.
