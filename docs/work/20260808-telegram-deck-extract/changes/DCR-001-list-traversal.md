## 변경 사유와 증거

TASK-03·09 실기에서 요구사항 가정 A-02("전보 행은 한 번에 하나만 펼쳐진다,
아코디언")가 실제 동작과 다름을 확인했다.

- 증거 1 (output/probe/snap_012449, 교전 탭): 미열람 단건 전보 3행이 **동시에
  펼쳐진 상태**로 표시.
- 증거 2 (snap_014131, 전체 탭): 단건 행은 펼침, `[N회 승]` **묶음 행은 접힘**
  — 혼재. 참고 이미지 img/4~6의 "아코디언"은 실제로는 단건/묶음 표시 규칙이었
  던 것으로 재해석됨.
- 증거 3 (snap_012358·nav_evidence): 아군이 수비인 전보는 패널 좌우 역할이
  반전(좌=아군이되 세로 라벨이 '수비', 우='공격'). 참고 이미지는 전부 아군=
  공격이라 좌=공격이 가정으로 굳어 있었음.
- 증거 4 (snap_013039): 행 헤더 **중앙의 위치 링크** 클릭 시 전보 화면이 닫히고
  월드맵 해당 좌표로 이동, 행군·주둔 버튼 팝업 노출(오클릭 사고 1회, 복구 완료).

## 기존 기준선과 설계

- REQ 가정 A-02: 아코디언(한 번에 하나만 펼쳐짐).
- DES-04 ListWalker: "다음 미처리 행을 클릭 → 펼침 패널 마커 대기 → 패널 크롭
  전달" — 모든 행을 클릭해 펼치는 절차.
- DES-05 DeckParser: 슬롯 side를 좌=attack, 우=defend로 고정 매핑(암묵).

## 제안 설계

1. **ListWalker 순회 전략**: 매 반복 행 재탐지(기존 유지) 후, **행별 펼침
   상태를 판정**해 — 이미 펼쳐진 행(행 앵커 근방에 '아군' 세로 라벨 존재)은
   클릭 없이 바로 파싱, 접힌 행(묶음 등)만 클릭해 펼친다. 행 클릭 지점은
   위치 링크·유저명·동맹명을 피한 **안전 x 지대**(우측 화살표 열 부근, TASK-10
   에서 실측 확정)로 한정한다.
2. **DeckParser 측면 매핑**: 패널 좌우 세로 라벨('공격'/'수비')을 템플릿
   판정해 좌측 3칸이 공격인지 수비인지 결정한다. BattleRecord의
   attacker/defender 의미는 불변 — 채우는 방향만 라벨에 따른다.

## 고려한 대안

- 대안 A: 모든 행을 접었다가 하나씩 펼치는 아코디언 강제 — 기각: 접기 클릭
  자체가 상태 의존적이고 클릭 수만 늘며, 이미 펼쳐진 정보를 버림.
- 대안 B: 세로 라벨 대신 유저명으로 아군 판정(내 닉네임 매칭) — 기각: 동맹원
  전보(내가 당사자가 아닌 전보)에서는 성립하지 않음.
