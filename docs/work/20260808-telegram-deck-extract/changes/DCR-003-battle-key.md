## 변경 사유와 증거

TASK-12 실기 scan run2(전체 이력 순회, 638건+ 시점 분석)에서 같은 전보가
다른 battle_key로 중복 저장되는 사례를 실증했다.

- 증거 1: 동일 장수 구성·동일 일시·동일 유저쌍의 두 레코드(455a7486/638f2c65)가
  attack2 병력 `10` vs `10011`로만 갈라짐. 두 레코드의 저장 캡처를 오프라인에서
  판독하면 **둘 다 10000으로 정독**(교차 프로세스 5회 반복 동일) — Windows OCR이
  실행 컨텍스트(승격·게임 부하·캡처 세션 동시 동작)에 따라 다른 값을 내는
  **비결정성**이 원인. 전처리 강화(닫힘 연산·괄호 복원, 2026-08-09 오전)로도
  구조적으로 제거 불가.
- 증거 2: 렌더 변형에서 레벨 판독이 실패(None)로 갈리는 partial 다수 —
  레벨 포함 키는 같은 전보를 (레벨 있음/없음) 두 키로 가른다.
- 대조: 랠리(같은 초·같은 유저쌍 다중 전투, 최대 8건 실증)는 장수 구성이 서로
  달라 장수 구성만으로 구분됨을 실기 데이터로 확인.

## 기존 기준선과 설계

- DESIGN v3 §데이터: `battle_key = sha1(battle_time | attacker_id | defender_id |
  정렬된 슬롯 튜플)` — 슬롯 튜플에 general_id·level·troops 포함.
- 알려진 한계: "일시·유저·덱이 완전히 동일한 두 전보는 1건으로 합쳐진다".

## 제안 설계

1. **키 재료를 결정적 요소로 한정**: `battle_key = sha1(battle_time |
   attacker_id | defender_id | 정렬된 (side, slot, general_id))`. 병력·레벨은
   레코드 값으로만 저장(전투별 이력 유지, CSV 포함 — 변경 없음).
2. **장수별 최신 레벨 조회 제공**(사용자 요청): `general_latest_levels()` —
   장수별 최신 battle_time 기준 레벨. `export`에 `generals_<날짜>.csv`
   (general_id, general, level, last_battle_time) 추가.
3. 알려진 한계 갱신: 같은 초·같은 유저쌍·**같은 장수 구성**의 다중 전투는
   1건으로 합쳐진다(기존 한계의 소폭 확대 — 병력만 다른 동시 전투 포함).

## 영향 범위

- 요구사항: FR-05·AC-03 의미 불변(이 변경으로 비로소 안정 충족). REQ 내용
  변경 없음 — 기준선 번호만 동기화(v4).
- 데이터: 스키마 불변(키 값만 변경). 기존 테스트 DB는 리셋(운영 데이터 없음,
  마이그레이션 불필요).
- 코드: `make_battle_key`, `general_latest_levels`(신규), `csv_export`(3종).
- 테스트: 키 민감도 테스트 의미 갱신(병력→장수 구성), 키 불변성·최신 레벨·CSV
  계약 테스트 추가.

## 고려한 대안

- 대안 A: OCR 전처리 추가 강화로 병력 판독 안정화 — 기각: 비결정성이 판독
  파이프라인 밖(엔진·실행 컨텍스트)에 있음이 실증되어 완전 제거 불가.
- 대안 B: 병력 반올림 값 포함 — 기각: `10` vs `10011` 같은 자릿수 붕괴는
  반올림으로 수렴하지 않음.
- 대안 C: 레벨 포함(병력만 제외) — 기각(사용자 결정): 레벨 판독 실패 변동으로
  중복 재발 경로가 남음. 레벨 요구는 최신 레벨 조회(위 2)로 충족.

## 구현된 코드의 처리

- 유지: 전체. 수정: datastore(make_battle_key·general_latest_levels),
  csv_export. 되돌림: 없음.

## 마이그레이션과 롤백

테스트 DB 리셋으로 갈음(output/deckscan.db 재생성). 코드는 파일 단위 복원 가능.

## 검증 방법

- 단위(TDD): 키가 병력·레벨 변동에 불변, 장수 구성에 민감, 슬롯 순서 무관.
  최신 레벨 조회(성장 반영). CSV 3종 계약.
- 실기: DB 리셋 후 제한 순회(--max-items) 연속 2회 — 카운트 불변(AC-03).

## 남은 위험

  표본에서 미관측. 수용.
- 병력 값 자체의 오독(키와 무관)은 잔존 — 캡처(NFR-03)로 사후 감사 가능.
