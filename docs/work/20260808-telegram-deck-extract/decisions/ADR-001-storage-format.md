# ADR-001: 추출 데이터 저장 형식 — SQLite 원본 + CSV 내보내기

> 문서 유형: `adr`
> 작업 ID: `20260808-telegram-deck-extract`
> 상태: `approved`
> 기준선: `v1` (승인일 2026-08-08)
> 작성일: 2026-08-08
> 최종 갱신: 2026-08-08
> 관련 문서: [REQ-20260808-telegram-deck-extract: 요구사항](../requirements.md), [DESIGN-20260808-telegram-deck-extract: 설계](../design.md)

## 요약

- 결정: 추출 데이터의 원본 저장소는 **SQLite 단일 파일 DB**로 하고, 사람 열람·엑셀 통계용 **CSV 내보내기** 명령을 별도로 제공한다. Markdown은 저장 형식으로 채택하지 않는다.
- 핵심 이유: 재실행 중복 방지(FR-05)를 기본 키 제약과 멱등 upsert로 가장 확실하게 만족하고, 통계 조회(AC-05)를 SQL로 바로 수행할 수 있으며, [map_search의 검증된 DataStore/CSV 내보내기 골격](file:///C:/src/git/map_search/src/mapscan/store/datastore.py)을 스키마만 바꿔 재사용할 수 있다.
- 주요 단점: DB 파일은 직접 열어 읽기 어렵다 → CSV 내보내기(UTF-8 BOM, 엑셀 한글 호환)로 보완한다.

## 배경

사용자 요청은 저장 형식을 md/csv/sql 중에서 "솔루션을 고민하여 정한다"이다. 이 작업의 목적은 교전 통계 정리이므로, 저장 형식은 (1) 전보 1건 : 장수 6건의 1:N 구조 표현, (2) 재실행·재순회 시 중복 방지, (3) 유저별·장수별 집계 질의, (4) 엑셀에서의 후속 분석을 지원해야 한다.

## 영향을 받는 요구사항과 제약

- [FR-04, FR-05, AC-03, AC-05](../requirements.md#기능-요구사항) — 영속 저장, 중복 방지, 재실행 멱등, 구조적 조회
- [NFR-03](../requirements.md#비기능-요구사항) — 레코드에 근거 캡처 경로 저장
- 제약: map_search 재사용 방침 — 동일 저장 계층을 쓰면 검증된 코드와 운영 경험(WAL, 중단·재개, UTF-8 BOM CSV)을 그대로 활용

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| ① Markdown 표 | 사람이 바로 읽음, diff 친화 | 중복 판정·집계를 전부 자작해야 함. 수백 행 이상이면 열람·편집 곤란. 통계 목적에 부적합 | 낮음(포기 시) |
| ② CSV 단일 원본 | 엑셀 즉시 호환, 구현 단순 | 멱등 저장을 위해 매 실행 전체 재읽기+키 관리 자작. 전보 1:N 장수 구조를 비정규화로 왜곡. 실행 중단 시 파일 파손 위험 | 낮음 |
| ③ SQLite 원본 + CSV 내보내기 (채택) | PK 제약으로 중복 방지가 구조적으로 보장. SQL 집계. WAL로 중단 내성. map_search 코드 재사용. CSV로 엑셀 요구도 충족 | 바이너리 파일이라 뷰어 필요. 파일 2계층(원본+내보내기) 관리 | — |

## 결정

SQLite를 유일한 원본(source of truth)으로 하고, `export` 명령이 UTF-8 BOM CSV를 생성한다. 스키마(전보 `battles` + 장수 `generals` 테이블, 내용 해시 기반 고유 키)는 [설계 문서의 데이터 설계](../design.md#데이터와-인터페이스)에서 정의한다.

## 이유

- 중복 방지(FR-05)가 코드 로직이 아니라 DB 제약으로 보장되어 실패 모드가 단순하다.
- "유저별 덱 구성" 같은 통계가 `GROUP BY` 한 줄로 끝난다(AC-05).
- map_search [ADR-003-storage](file:///C:/src/git/map_search/docs/work/20260801-worldmap-land-scan/decisions/ADR-003-storage.md)와 동일 노선이라 저장 계층을 스키마 교체만으로 이식할 수 있다.

## 결과와 감수할 단점

- 데이터 확인 시 DB 뷰어 또는 `export` 실행이 필요하다. 실행 종료 시 요약 보고(FR-06)로 즉시 확인 수요를 일부 흡수한다.
- Markdown 보고서가 필요해지면 저장 형식이 아니라 **출력 형식**으로 추후 추가한다(범위 밖).
