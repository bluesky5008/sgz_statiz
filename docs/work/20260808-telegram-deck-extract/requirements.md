## 문제와 목적

동맹 전보의 교전 기록에는 아군·적군 덱 구성(유저, 장수, 레벨)이 표시되지만, 게임 클라이언트 밖으로 내보내는 기능이 없어 통계 정리를 하려면 수작업으로 옮겨 적어야 한다. 이 작업은 PC 클라이언트를 자동 제어하여 교전 전보를 하나씩 열람하고, 화면 캡처와 이미지 인식으로 덱 정보를 추출해 저장함으로써 교전 통계 정리(예: 상대 유저별 덱 구성 파악)를 가능하게 한다.

## 대상과 시나리오

- 대상 사용자: 본인(로컬 PC에서 스크립트를 직접 실행하는 단일 사용자).
- 주 시나리오: 클라이언트가 실행·로그인되어 메인 화면인 상태에서 사용자가 스크립트를 실행하면, 도구가 `더 보기 → 동맹 → 전보 → 교전 탭`으로 자동 이동한 뒤 전보 행을 하나씩 펼쳐 덱 정보를 추출·저장하고, 종료 시 처리 결과를 요약 보고한다.

## 범위

### 포함

- 구동 시 대상 클라이언트 창의 동적 탐지와 다중 후보 시 사용자 선택 (FR-08, [DCR-002](./changes/DCR-002-client-selection.md))
- 메인 화면에서 동맹전보 교전 탭까지의 자동 화면 이동
- 교전 탭 전보 목록의 순회(행 펼치기, 필요 시 목록 스크롤)
- 펼쳐진 덱 패널에서 공격·수비 유저명, 장수 6인(공격 3, 수비 3)의 장수명·레벨 추출
- 추출 데이터의 영속 저장(형식은 ADR-001에서 결정)과 재실행 시 중복 방지
- 검증·디버깅용 원본 캡처 이미지 보관

### 제외

- 약탈·공성 등 교전 이외 탭의 전보 처리(구조 확장은 고려하되 구현하지 않음)
- 게임 상태를 변경하는 조작(전보 검색·필터 변경, `전체 읽음` 클릭 등). 단, 화면 이동과 행 펼치기에 필요한 클릭·스크롤은 허용
- 통계 분석·시각화 자체(저장된 데이터로 추후 별도 작업)
- 클라이언트 자동 실행·로그인
- 실행 종료 후 게임 화면 원상 복귀(동맹전보 화면에 머문 채 종료하며, 복귀는 사용자가 수동 수행)

## 기능 요구사항

- FR-01: 메인 화면에서 `더 보기 → 동맹 → 전보 → 교전 탭` 순서로 자동 이동해야 한다. 각 단계는 클릭 후 목표 화면이 표시되었는지 판정하고 나서 다음 단계로 진행해야 한다.
- FR-02: 교전 탭의 전보 목록에서 전보 행을 위에서부터 하나씩 펼쳐 덱 패널을 표시해야 한다. 전보가 아닌 행(격전 보상 배너 등)은 건너뛰어야 한다.
- FR-03: 펼쳐진 덱 패널에서 다음을 추출해야 한다: 공격 측 유저명, 수비 측 유저명, 장수 카드 6장 각각의 장수명과 레벨(공격 3, 수비 3).
- FR-04: 추출한 전보 1건을 1개 레코드로 영속 저장해야 한다. 저장 형식·스키마는 [ADR-001](./decisions/ADR-001-storage-format.md)의 결정을 따른다.
- FR-05: 같은 전보를 다시 처리해도 중복 레코드가 생기지 않아야 한다(재실행 및 목록 재순회 시).
- FR-06: 실행 종료 시 처리한 전보 수, 저장 성공 수, 인식 실패 수와 실패 사유를 요약 보고해야 한다.
- FR-07: 처음 등장한 유저·장수는 안정적 식별자(ID)로 저장하되 사람이 읽는 이름 라벨은 `pending`(제안값 포함) 상태로 두고, 사용자가 라벨을 확정하는 등록 절차를 제공해야 한다. 등록된 라벨은 이후 실행에서 자동 적용되어야 한다. (근거: [ADR-002](./decisions/ADR-002-recognition-strategy.md) — OCR만으로는 이름의 안정적 그룹핑이 불가함이 프로토타입에서 실증됨)
- FR-08 (v3, [DCR-002](./changes/DCR-002-client-selection.md)): `scan`·`probe` 구동 시 제목 매칭으로 클라이언트 창 후보를 동적 탐지해야 한다. 후보가 여럿이고 대화형 실행이면 후보 목록(순번·pid·창 위치·크기·권한)을 표시하고 번호 선택을 받은 뒤 선택한 창을 전면에 올려 사용자 확인(y/n)을 받고 진행해야 한다. 후보가 하나면 대상 창 정보를 출력하고 자동 진행한다. `--hwnd` 지정 시 탐지·선택을 생략한다. 비대화형 실행에서 다중 후보면 후보 목록과 함께 실행을 거부해야 한다(종료 코드 1, 프롬프트 대기 금지).

## 비기능 요구사항

- NFR-01 (강건성): 개별 전보의 인식 실패가 전체 실행을 중단시켜서는 안 된다. 실패한 전보는 원본 캡처와 함께 실패로 기록하고 다음 전보로 진행해야 한다.
- NFR-02 (화면 대기): 화면 전환 대기는 고정 시간 대기가 아니라 화면 상태 판정(템플릿 매칭 등) 기반이어야 하며, 상한 시간 초과 시 해당 단계를 실패로 처리해야 한다.
- NFR-03 (검증 가능성): 추출 레코드에는 근거가 된 캡처 이미지 경로를 함께 저장하여 사후 검증이 가능해야 한다.
- NFR-04 (환경 호환): [map_search](file:///C:/src/git/map_search)와 동일한 클라이언트 실행 환경(창 제목 `삼국지-전략판`, 동일 해상도)에서 동작해야 한다.

## 인수 조건

- AC-01: 클라이언트가 메인 화면인 상태에서 도구를 실행하면, 사용자 개입 없이 동맹전보 화면의 교전 탭까지 도달한다.
- AC-02: [img/4.png](../../../img/4.png)과 동일한 덱 패널 화면에 대해, 공격 유저명 `토리의사생활`, 수비 유저명 `元이설탱스`, 공격 장수 `(50, 가후), (50, 곽가), (50, 양기)`, 수비 장수 `(50, 법정), (49, TBD — 판독 후보 '성채', 구현 시 실기 확대 화면으로 확정), (50, 관우)`를 추출한다(정지 이미지 기반 오프라인 검증 허용. 장수·유저 "이름"은 FR-07의 라벨 등록 후 조회 기준).
- AC-03: 교전 탭에서 전보 N건을 처리한 뒤 저장소에 정확히 N건의 레코드가 존재하고, 같은 조건으로 재실행해도 레코드 수가 늘지 않는다.
- AC-04: 인식 실패 전보가 1건 이상 있어도 나머지 전보는 정상 처리되며, 실행 요약에 실패 건수와 사유가 보고된다.
- AC-05: 저장된 데이터는 (전보, 진영, 장수 슬롯) 단위로 유저명·장수명·레벨을 조회할 수 있는 구조다.
- AC-06: 미등록 장수·유저가 등장하면 `pending` 식별자로 저장되고, 라벨 등록 절차로 이름을 확정하면 기존·이후 레코드 조회에 그 이름이 반영된다.
- AC-07 (v3, [DCR-002](./changes/DCR-002-client-selection.md)): 클라이언트 창이 2개 실행된 상태에서 대화형으로 scan을 실행하면 후보 목록이 표시되고, 번호 선택과 전면 확인 후 선택한 창을 대상으로 스캔이 수행된다. 후보가 1개면 선택 절차 없이 진행된다.

## 제약과 의존성

- 실행 환경: Windows 11, 삼국지 전략판 PC 클라이언트(창 모드). 사실: 참고 이미지의 창 2546×689는 map_search 캘리브레이션(클라이언트 2544×657 + 테두리·제목 표시줄)과 일치 — 동일 창 크기 전제가 성립한다. 다른 크기에서는 실행을 거부한다([설계](./design.md#설계-목표와-제약)).
- 클라이언트 제어·캡처·인식 기술은 [map_search](file:///C:/src/git/map_search)의 기존 구현을 재사용한다(동일 환경 전제). 재사용 범위는 [설계](./design.md#컴포넌트와-책임)에서 확정했다.
- 게임 UI 텍스트는 한국어이며, 유저 닉네임에는 비한글 문자가 포함될 수 있다(사실: 참고 이미지에서 `元이설탱스` 확인). 인식 방식은 [ADR-002](./decisions/ADR-002-recognition-strategy.md)를 따른다.
- 게임 클라이언트 업데이트로 UI 배치가 바뀌면 좌표·템플릿 갱신이 필요하다(운영상 제약으로 수용).

## 가정과 미해결 질문

- 가정 A-01: 도구 실행 시점에 클라이언트는 실행·로그인 완료 상태이며 메인 화면(월드맵)이다. 다른 화면이면 실패로 종료해도 된다.
- 가정 A-02 (v2, [DCR-001](./changes/DCR-001-list-traversal.md)): 단건 전보 행은 기본적으로 펼쳐져 표시되고 `[N회 승/무]` 묶음 행은 접혀 표시되며, 여러 행이 동시에 펼쳐져 있을 수 있다(2026-08-09 실기 관찰). 접힌 행은 클릭으로 펼친다. ~~(v1: 아코디언 — 한 번에 하나만 펼쳐짐)~~
- 가정 A-03: 덱은 공격 3장수 + 수비 3장수 구성이다(참고 이미지 기준). 슬롯이 비어 있는 덱(장수 1~2인)이 나타날 수 있으며, 이 경우 있는 슬롯만 저장한다.
- 가정 A-04: `[N회 승/무]`로 묶인 행도 펼치면 덱 패널 1개가 표시되며, 그 1개를 해당 행의 레코드로 저장하는 것으로 충분하다(참고 이미지 4~6의 시연 동작과 동일).
결정된 질문(2026-08-08 사용자 응답, 승인 관문):

- Q-01 → 결정: 실행 시점에 목록에 존재하는 교전 전보 **전체를 스크롤하며 처리**한다.
- Q-02 → 결정: 전투 시각, 승/무/패 결과, 장수별 병력 수, 동맹명을 **모두 저장**한다.
- Q-03 → 결정: **수동 1회 실행(CLI)** 방식으로 한다. 주기 실행은 범위 밖.

## 위험

- RISK-01: 장수명·유저명 OCR 오인식 가능성(장식 배경 위 한국어 소형 글꼴). 프로토타입 P-01에서 위험이 실증되어 [ADR-002](./decisions/ADR-002-recognition-strategy.md)의 템플릿 식별 구조로 구조적으로 회피한다(잔여 위험은 [설계 RISK-04](./design.md#위험)).
- RISK-02: 전보 목록의 동적 변화(실행 중 새 전보 도착, 스크롤 위치 변동)로 인한 누락·중복. 완화: FR-05 중복 방지와 레코드 동일성 키 설계.
- RISK-03: 클라이언트 창 크기·해상도가 참고 이미지와 다르면 좌표·템플릿이 어긋날 수 있음. 완화: NFR-04 전제 명시, 실행 시 창 크기 검증.
