## 문제와 목적

deckscan DB에는 전보별 덱(유저·장수·레벨·병력·승패·일시)이 쌓이지만 조회 수단이 원시 CSV뿐이다. 정찰(상대 유저의 현재 덱 파악)과 분석(픽률·조합 승률·전적)을 위해 집계·시각화 계층을 추가한다.

## 대상과 시나리오

- 대상 사용자: 본인(로컬 단일 사용자).
- 주 시나리오: scan·label 운영으로 데이터를 쌓은 뒤 `deckscan stats`를 실행하면 `output/stats/`에 HTML 리포트와 집계 CSV가 생성되고, 브라우저로 열어 상대 유저 덱·픽률·조합 승률·전적을 열람한다.

## 범위

### 포함

- 통계 4종(사용자 결정 2026-08-09): ① 상대 유저별 최신 덱(+덱 변경 이력), ② 장수 픽률·등장 빈도, ③ 덱 조합별 승률, ④ 유저별 전적
- 단일 파일 HTML 리포트(로컬 생성, 외부 리소스·네트워크 없음)
- 통계별 집계 CSV(UTF-8 BOM — 엑셀 피벗용)

### 제외

- 수집 계층(작업 1) 변경, DB 스키마 변경(읽기 전용 접근)
- 웹 서버·자동 갱신·주기 실행, 외부 차트 라이브러리 의존
- 병력 수 기반 통계(값 신뢰도 한계 — deckscan 알려진 한계 참조)

## 기능 요구사항

- FR-01 (상대 유저별 최신 덱): 유저별로 가장 최근 전투 기준 덱 구성(장수 3인 + 장수별 최신 레벨)과 덱 구성 변경 이력(구성이 달라진 시점 목록)을 제공해야 한다.
- FR-02 (장수 픽률): 장수별 등장 횟수·비율을 전체와 측면(공격/수비)별로 제공해야 한다.
- FR-03 (덱 조합별 승률): 장수 3인 조합(슬롯 순서 무관) 단위로 승/무/패 횟수와 승률을 제공해야 한다. 승패는 조합이 속한 측의 관점으로 정규화한다 — 전보의 `result`(아군 관점)와 아군 측 판별(A-01)로 각 측의 결과를 유도한다.
- FR-04 (유저별 전적): 상대 유저별 승·무·패 집계와 최근 교전 일시를 제공해야 한다.
- FR-05 (출력): 위 통계를 단일 HTML 리포트와 통계별 CSV로 `output/stats/`에 생성해야 한다. HTML은 외부 요청 없이 열려야 한다.
- FR-06 (라벨 표기): 라벨 미확정 식별자는 `#ID(제안값)` 형식으로 표기하고, `label`로 확정하면 재생성 시 이름이 반영되어야 한다.

## 비기능 요구사항

- NFR-01 (비침습): 수집 DB는 읽기 전용으로 연다. 통계 생성이 수집 데이터를 변경하지 않는다.
- NFR-02 (재현성): 같은 DB에서 같은 명령은 같은 수치를 생성한다.
- NFR-03 (불완전 데이터 내성): parse_status가 `failed`인 레코드와 일시 없는 레코드는 시계열 통계에서 제외하되 제외 건수를 리포트에 표기한다.

## 인수 조건

- AC-01: 픽스처 DB(유저·전투 표본)에서 `stats` 실행 시 HTML 파일이 생성되고, 상대 유저 절에 최신 전투 기준 덱(장수 3인·최신 레벨)이 표시된다.
- AC-02: 장수 픽률 표의 등장 횟수·비율이 픽스처 기대값과 일치한다(전체·측면별).
- AC-03: 아군이 공격 승리한 픽스처 전투에 대해, 공격 조합에 승 1이, 수비(상대) 조합에 패 1이 집계된다(무승부는 양측 무 1).
- AC-04: 유저별 전적 표의 승·무·패·최근 일시가 픽스처 기대값과 일치한다.
- AC-05: 집계 CSV의 수치가 HTML 리포트와 동일하다.
- AC-06: 라벨 미확정 식별자는 `#ID(제안값)`으로 표기되고, 라벨 확정 후 재생성하면 확정 이름으로 표기된다.

## 제약과 의존성

- 데이터 원천: deckscan DB(기준선 v5 스키마 — battles·deck_slots·identities). 완전 덱(양측 3장수)만 저장되므로 조합 통계의 전제 성립.
- 현재 수집 데이터는 소량(5건) — 통계 도구는 데이터 축적과 병행 운영된다.
- Python ≥3.12, 추가 외부 의존성 없이 표준 라이브러리로 HTML 생성.

## 가정과 미해결 질문

- 가정 A-01 (아군 측 판별): 레코드의 `result`는 아군 관점이며 아군 측(공격/수비)은 동맹으로 판별한다 — 기본값은 DB에서 가장 빈번한 동맹을 아군 동맹으로 자동 추정하고, `--alliance <라벨|ID>`로 재정의할 수 있다.
- 가정 A-02 (조합 정규화): 덱 조합은 장수 3인 집합(슬롯 순서 무관)이다. 같은 장수 집합의 슬롯 배치 차이는 같은 조합으로 본다.

## 위험

- RISK-01: 아군 동맹 자동 추정 오판(동맹 라벨 미확정·소량 데이터) → `--alliance` 재정의와 리포트에 추정 결과 표기로 완화.
- RISK-02: 수집 데이터 소량 단계에서 승률 통계의 통계적 유의성 부족 → 표본 수(n)를 모든 승률 표기에 병기.
